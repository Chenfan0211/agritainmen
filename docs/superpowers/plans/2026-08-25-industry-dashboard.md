# 产业数据监管与赋能驾驶舱实施计划

## 目标

新增独立 uni-app PC H5 dashboard，统一聚合现有各端共享数据；运营后台门店增加地址和可插拔高德/腾讯地理编码，dashboard 使用已解析的门店坐标绘制地图。

## 全局约束

- 保留工作区中现有未提交改动，不提交、不推送、不合并。
- 使用 TDD：共享行为先写失败测试，再实现。
- dashboard 只读，H5 单源部署路径为 `/dashboard/`。
- 用户演示订单不进入监管指标；区域权限在聚合前应用。

## Task 1：共享模型、地理编码与门店坐标

- 扩展 `FarmStore` 地址、定位状态和 GCJ-02 坐标字段。
- 新增高德、腾讯适配器和按顺序回退的地理编码服务。
- 为演示门店补充地址和预置坐标。
- 运营后台门店新增/编辑时解析地址，失败保留地址并清除旧坐标。
- 增加地理编码与门店保存单元测试。

## Task 2：驾驶舱数据源与聚合器

- 定义三角色账号、区域范围、快照、风险和建议类型。
- 从共享门店、账号、目录、订单、预约、券、直播、售后和结算生成只读快照。
- 实现权限过滤、演示订单排除、指标口径、风险和赋能规则。
- 增加聚合、权限和异常数据单元测试。

## Task 3：独立 dashboard 应用

- 新增 `apps/dashboard` uni-app H5 工程、登录、角色菜单和综合驾驶舱。
- 使用 ECharts 绘制地图、趋势、供需和排行图表。
- 支持区域下钻、时间筛选、刷新、全屏、口径说明和错误/空态。
- 使用平台变更订阅在同源其他端写入后刷新快照。

## Task 4：构建与 E2E 集成

- 增加根脚本、单源构建 `/dashboard/` 和第 8 个入口资源检查。
- 增加角色权限、跨端联动、地图点位和 1920/1440/1366 布局 E2E。
- 运行单测、类型检查、构建、单源资源检查和 E2E。
