# 用户端小程序化布局、直播画面与演示订单设计

## 目标

将用户端 H5 固定为 375 x 812 的手机画框预览，在首页和“我的”页提供统一的全屏直播间入口，并在首次登录且用户无订单时补充可识别、不会污染供应商履约数据的演示订单。

## 布局

- H5 的 `.app-shell` 宽度固定为 375px、最小高度为 812px并在桌面居中，页面背景使用中性灰。
- H5 的底部 Tab、购物车栏、底部弹层遮罩和直播间都固定在同一 375px 画框内。
- 微信小程序使用 `100vw`、`100vh`、`--status-bar-height` 和底部安全区，不显示画框。
- 删除桌面端 720px 放大规则，375px 及更窄视口不得出现横向滚动。

## 直播

- `apps/user/src/config/live.ts` 集中导出演示视频地址和默认封面。
- 首页展示带视频、直播状态、主播和观看人数的直播卡片；没有处于直播状态且关联有效套餐的直播时显示禁用空态。
- 首页卡片和“我的”页入口打开同一个全屏直播间。视频区约占 45%，下方按门店展示过滤后的有效套餐。
- 立即购买使用现有 `store.buyLivePackage()`，选择首个库存大于 0 的 SKU。成功后产生已支付券订单和待结算推广佣金。
- 有效套餐必须处于上架状态、存在未退役且有库存的 SKU，并属于直播关联门店。直播下架或没有有效套餐时不可进入。

## 演示订单

- 首次登录、当前用户没有 C 端订单且未设置禁用标记时播种。
- 写入 4 条带 `DEMO-` 前缀的 C 端订单，覆盖待支付、备货中、已发货、已收货/部分售后，包含地址、物流快照和 1 至 2 个供应商子订单。
- 写入 2 条券订单：一条当前已支付；一条先核销后退款并同时保留 `redeemedAt`、`refundedAt`，以两条记录覆盖已支付、已核销、已退款生命周期。
- 成功写完两类订单后才写 `agritainment-user-demo-orders-seeded-${userId}`。禁用键为 `agritainment-user-demo-orders-disabled`。
- 只写 `agritainment-platform-c-orders` 和 `agritainment-platform-vouchers`，不生成 `agritainment-platform-orders` 供应商履约单，不改库存、不生成真实结算。
- 订单页以“演示订单”标签区分 `DEMO-` 数据，真实订单行为保持不变。

## 验证

- Store 单测验证禁用、首次播种、结构完整、生命周期覆盖、只播种一次及不生成供应商履约单。
- E2E 的通用登录辅助函数设置禁用键；单独的演示场景验证直播卡片、全屏直播间、购买和演示订单展示。
- 桌面 1280px 与手机 375px 视口验证画框边界、固定栏和无横向溢出。
- 回归命令：`pnpm test`、`pnpm typecheck`、`pnpm build:single-origin`、`pnpm check:single-origin`、`pnpm test:e2e`、`pnpm test:e2e:user`。
